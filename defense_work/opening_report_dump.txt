ROW3: 1．选题依据、国内外研究概况 / 选题背景：中医药知识广泛分布于教材、经典古籍、方剂资料和现代文献等不同载体中，存在知识来源分散、内容形式多样等问题。传统信息检索主要依赖关键词匹配，在复杂语义查询方面存在一定局限。随着大语言模型的发展，其在知识问答方面具有较强能力，但直接依赖模型自身知识容易出现知识依据不足等问题。检索增强生成（RAG）通过检索外部知识辅助生成，为专业领域知识问答提供了新的思路。 / 国内外研究现状及水平：国外关于检索增强生成（RAG）的研究起步较早。Lewis等人在2020年发表了《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》，研究了将外部知识检索与大语言模型相结合的方法，为知识问答系统的发展提供了新的思路。随着相关技术的发展，研究逐渐涉及混合检索、检索结果重排序和问答效果评估等方面，为提高系统的检索质量和回答准确性提供了技术参考。 / 国内相关研究逐渐向中医药知识问答领域发展。张玉铭等人开展了基于检索增强生成技术的中医药问答研究，将中医药相关资料与大语言模型相结合，为中医药知识问答提供了新的实现思路。此外，部分研究开始探索知识图谱与大语言模型的结合，通过利用知识图谱中的实体及关系信息，为问答系统提供更加明确的知识支持。这些研究表明，将中医药知识库与大语言模型相结合，是当前中医药智能问答系统的一种重要研究方向。 / 总体来看，国内外相关研究在检索增强生成、领域知识库构建和智能问答等方面已取得一定进展，但仍有进一步完善的空间。中医药知识来源广泛，不同类型的资料在内容结构和表达方式上存在差异，因此需要对知识资源进行统一管理。同时，不同问题对检索方式的要求也有所不同，如何提高检索结果与用户问题之间的相关性，以及如何展示回答所依据的知识来源，仍值得进一步探索。本课题拟围绕中医药知识资源管理、知识检索和智能问答等功能开展设计与实现，为用户提供具有知识依据的中医药问答服务。 / 研究目标：本课题旨在设计并实现一个中医药知识问答系统，建立中医药领域知识库。系统主要实现中医药知识资源管理、知识检索和智能问答等功能，对中药、方剂、中医理论及相关文献等知识进行整理与管理，为用户提供便捷的知识查询服务。同时，结合大语言模型与知识检索技术，根据用户提出的问题检索相关知识并生成回答，并尽可能展示相应的知识来源，提高问答结果的可靠性和可追溯性。
ROW4: 主要研究（设计）内容、研究（设计）方法及技术路线 /  /  / 2.1 主要设计内容 / 本课题围绕中医药知识资源管理与智能问答系统的设计与实现展开，针对中医药知识资源类型多样、知识查询方式相对单一、个人学习资料缺乏统一管理方式，以及大语言模型回答缺少明确知识依据等问题，结合中医药知识的专业特点和用户的实际使用需求，设计并实现集知识资源管理、知识检索、个人文档管理、智能问答及系统管理于一体的综合性应用系统。系统以中医药知识资源的组织与利用为基础，通过对不同类型知识资源进行分类管理，并将知识检索与大语言模型生成能力相结合，为用户提供中医药知识查询、个人资料检索和智能问答等服务。主要设计内容包括以下几个方面。 / （1）普通用户端功能设计 / 普通用户端主要面向中医药知识学习、查询及个人资料管理等使用场景，围绕智能问答、知识资源浏览、个人文档管理和个人中心等方面开展设计，满足用户获取中医药知识、查询相关资料以及管理个人学习内容的需求。 / 1.智能问答功能设计。 / 针对用户通过自然语言提出中医药知识问题的需求，设计智能问答功能。用户可以直接输入问题，由系统对问题进行分析，并根据问题内容选择相应的处理与检索方式。在知识检索环节，系统结合关键词检索和向量语义检索，从已有知识资源中查找相关内容，再对候选检索结果进行融合与重排序，筛选出与问题相关性较高的知识资料。系统将筛选后的知识内容与用户问题相结合，提交给大语言模型生成回答，使回答能够参考系统已有的中医药知识资源，而不是完全依赖模型自身的知识。 / 在交互方式方面，系统支持多轮对话，使用户能够围绕前一个问题继续追问，逐步补充查询条件或深入了解相关知识。同时，通过流式输出方式逐步展示生成内容，减少用户等待完整回答的感受。系统还提供答案来源引用功能，将回答与相关知识资料进行关联，方便用户查看参考内容，进一步了解回答的知识依据。 / 2.知识资源浏览与检索功能设计。 / 针对中医药知识类型多样、不同用户具有不同查询需求的特点，系统对中医药知识资源进行分类组织，并提供相应的浏览与检索功能。用户可以按照资源类别查看相关知识，也可以通过输入关键词或自然语言查询内容，查找所需的中医药资料。 / 在检索方式上，系统结合关键词匹配与向量语义检索。关键词检索侧重于查询词与知识文本之间的匹配，向量语义检索则用于查找语义上相关的内容。通过融合不同检索方式的结果，并对候选内容进行重排序，系统能够从不同角度筛选与查询需求相关的知识资源。检索结果可作为独立的知识查询结果展示，也可为后续智能问答提供参考内容，从而实现知识浏览、信息查询与智能问答之间的衔接。 / 3.个人文档管理功能设计。 / 针对用户在中医药学习过程中积累的电子资料较多、文档内容不便直接检索的问题，设计个人文档管理功能。系统支持用户上传 PDF、Word、TXT 等常见格式的文档，并对上传文件进行相应的解析和文本提取，获取其中可用于检索的文字内容。 / 在文档处理过程中，系统对提取出的文本进行规范化整理，并按照适当的文本长度划分为多个内容片段，再对片段进行向量化处理，建立面向个人资料的检索基础。通过上述处理，原本以文件形式保存的资料可以进一步参与知识查询。用户能够围绕个人上传的文档查找相关内容，减少逐份打开文件、手动查找信息的操作，提高个人学习资料的利用效率。 / 4.个人中心功能设计。 / 为方便用户管理个人信息及查看历史使用情况，系统设计个人中心模块，提供个人信息管理、历史问答会话查看及个人设置等功能。用户可以查看和维护个人相关信息，根据实际需要调整系统提供的个人设置，并通过历史会话功能回顾之前提出的问题及系统生成的回答。 / 个人中心将用户信息管理与日常知识查询功能相结合，使用户能够持续使用系统开展知识学习和问题查询，并在后续使用过程中回顾已有的问答记录，增强系统使用的连续性与便利性。 / （2）知识资源管理功能设计 / 知识资源管理功能主要面向管理员，负责对系统中的中医药知识进行统一组织、维护和更新，为普通用户的知识浏览、检索查询及智能问答提供基础资源。 / 1.中医药知识资源分类管理。 / 结合中医药知识的内容特点，系统对知识资源进行分类管理，主要包括中药、方剂、中医理论和中医药文献等类型。针对不同类别的资源，分别组织相应的信息内容。 / 中药资源主要围绕中药名称、别名、性味、归经及功效等信息进行管理；方剂资源主要围绕方剂名称、组成药物、功效、主治及用法等信息进行管理；中医理论资源主要管理理论名称、相关内容和知识来源；中医药文献资源则围绕文献名称、作者、年代、摘要及正文内容等信息进行组织。通过分类管理，使不同类型的知识资源具有较为清晰的组织结构，便于后续维护、浏览和检索。 / 2.知识资源信息维护。 / 针对知识资源在使用过程中可能需要补充、修改和更新的问题，系统提供相应的资源维护功能。管理员可以对已有资源进行查询和浏览，根据实际需要新增资源、修改已有信息或删除不再需要的内容。同时，针对不同类型资源的属性特点，系统对相关信息进行分类组织，减少不同类型知识内容混杂所带来的管理困难。 / 通过资源维护功能，可以对系统中的知识内容进行持续更新，保持知识资源的完整性和可用性，为用户查询和智能问答提供较为稳定的知识基础。 / 3.知识库管理与资源批量导入。 / 为满足中医药知识资源集中管理和批量维护的需求，系统设计知识库管理及资源批量导入功能。管理员可以对知识库中的资源进行统一维护，并通过批量导入方式处理已有的结构化知识资料，减少逐条录入所需的重复操作。 / 在资源导入过程中，系统根据资源内容进行相应的解析、整理与格式处理，并对需要进入检索流程的文本内容进行规范化处理。对于适合建立向量索引的知识内容，系统进一步完成文本分块与向量化处理，使知识资源能够参与后续的语义检索及智能问答。通过上述设计，将知识资源的业务管理与问答检索所需的知识准备过程相衔接。 / （3）基于检索增强生成的智能问答设计 / 智能问答是本系统的重要组成部分。针对单纯依靠大语言模型回答专业知识问题时可能出现的知识依据不足、回答与现有资料不一致等问题，系统将问题分析、知识检索、结果筛选、证据判断与答案生成等环节结合起来，形成完整的检索增强生成处理流程。 / 1.用户问题分析与检索策略设计。 / 当用户提交问题后，系统首先对问题内容进行分析，识别问题中涉及的知识实体及查询意图，为后续检索提供依据。对于包含中药、方剂或其他中医药专业概念的问题，系统结合已有知识资源识别相关实体，并根据问题特点选择适当的检索处理方式。对于内容较复杂、可能涉及多个知识点的问题，系统可按照已有处理逻辑进行问题拆分，以便分别查找相关知识，再为后续回答生成提供支持。 / 通过问题分析与检索策略处理，系统能够在进入知识检索环节前对用户需求进行初步整理，使后续检索不局限于对原始问题进行简单的文本匹配。 / 2.关键词检索与向量语义检索设计。 / 针对不同表达方式可能影响检索结果的问题，系统采用关键词检索与向量语义检索相结合的方式获取候选知识。关键词检索能够根据查询词与知识内容之间的匹配情况查找相关资料；向量语义检索则通过对问题文本和知识文本进行向量表示，查找语义上较为接近的内容。 / 两种检索方式分别从文本匹配和语义相关性等角度获取候选结果，弥补单一检索方式可能存在的不足。通过结合不同检索途径，系统能够更全面地查找与用户问题相关的中医药知识，为后续的结果融合与排序提供候选内容。 / 3.检索结果融合与重排序设计。 / 由于不同检索方式得到的候选结果及其排序可能存在差异，系统进一步对检索结果进行融合处理，将不同检索途径获取的相关知识进行整合。在此基础上，利用重排序机制重新评估候选内容与用户问题之间的相关程度，调整知识内容的排列顺序，使更符合查询需求的资料优先进入后续处理环节。 / 通过检索结果融合与重排序，系统能够减少仅依赖单一检索结果顺序可能带来的影响，为大语言模型提供经过进一步筛选的参考知识，提高检索内容与用户问题之间的匹配程度。 / 4.知识关联与检索结果补充设计。 / 针对部分问题涉及明确中医药实体及其关联知识的情况，系统结合知识实体识别和相关知识关联处理，对检索结果进行必要的补充。通过查找相关实体及其关联内容，可以为问题提供除文本匹配结果之外的补充信息，帮助系统获取与问题相关的知识联系。 / 同时，系统结合资源类型、知识内容及相关来源信息对候选结果进行整理，尽可能减少重复或不符合当前查询需求的内容，为后续证据判断和答案生成提供相对清晰的知识上下文。 / 5.检索证据判断与回答控制设计。 / 为减少知识依据不足时直接生成回答所带来的问题，系统在答案生成前对检索结果的相关程度进行判断。当检索内容能够为用户问题提供相应支持时，系统继续进行答案生成；当现有检索结果相关性不足时，则按照系统已有的处理逻辑进行进一步检索或触发相应的回答限制，降低系统在缺乏充分知识依据时给出过度肯定回答的可能性。 / 通过证据判断与回答控制，将知识检索结果与答案生成过程联系起来，使系统不仅关注能否生成回答，也关注检索到的资料是否能够支持回答，从而提高智能问答的可控性。 / 6.大语言模型答案生成与回答检查设计。 / 在完成相关知识检索与证据筛选后，系统将用户问题和检索到的相关知识组织为模型输入，由大语言模型结合这些内容生成回答。通过将外部知识资料引入生成过程，系统能够围绕已有中医药知识资源回答用户提出的问题。 / 在回答生成后，系统结合已有的回答检查机制，对生成内容进行必要的评估，并根据处理结果决定是否接受当前回答、进行调整或重新尝试。通过这一设计，将知识检索、答案生成与回答检查衔接起来，降低回答内容与检索依据不一致的风险。 / 7.答案来源关联与问答记录设计。 / 为提高智能问答结果的可追溯性，系统在生成回答的同时处理相应的知识来源信息，并将回答与相关知识资源建立关联。用户可以通过答案中的来源信息查看相应资料，了解回答参考了哪些知识内容，便于进一步阅读和核对。 / 此外，系统对用户的问答交互进行相应记录，支持历史会话查询及连续对话所需的上下文管理，使问答功能不仅能够完成单次问题处理，也能够满足用户持续学习和回顾历史内容的需求。 / （4）系统管理与权限控制设计 / 为保障系统不同角色的正常使用，系统设计相应的用户管理和权限控制功能，对普通用户与管理员的操作范围进行区分。 / 1.用户账号管理。 实现用户账号相关信息的管理，支持管理员查看和维护用户信息，为系统用户的统一管理提供基础。 / 2.角色与权限管理。 根据普通用户和管理员的不同职责设置相应的功能访问权限，使普通用户能够使用知识浏览、检索及智能问答等功能，管理员能够开展知识资源维护、用户管理和相关管理操作。 / 3.管理记录与系统维护。 结合系统已有的管理记录查看功能，方便管理员了解相关管理操作和系统运行情况，为日常维护与问题排查提供支持。 / 4.外部大模型服务集成。 系统通过外部大语言模型服务完成问答内容生成，将问题分析、知识检索与证据筛选等处理结果传递给模型，并对模型返回的内容进行后续处理。大语言模型主要承担自然语言回答生成任务，知识资源组织、检索策略、结果筛选、证据判断和来源关联则由系统自身的相关功能协同完成，从而形成较为完整的智能问答流程。 / （5）系统整体功能集成 / 在完成各功能模块设计的基础上，对普通用户端、知识资源管理功能及智能问答功能进行整合。普通用户可以通过统一的操作入口开展知识浏览、检索查询、个人文档管理和智能问答；管理员可以通过相应管理功能维护知识资源、管理用户及更新知识库内容。当知识资源发生新增或更新时，系统按照相应的资源处理流程完成内容整理及检索所需的数据准备，使相关知识能够用于后续查询与问答。 / 通过各模块之间的协同，实现从知识资源维护、知识检索到智能问答及答案来源展示的完整业务流程，形成面向中医药知识学习与查询需求的综合应用系统。 /  /  /  / 2.2研究（设计）方法：文献研究法：查阅相关研究资料。系统设计法：完成系统功能及数据库设计与实现。测试法：对系统功能进行测试。 / 2.3技术路线：本系统采用前后端分离架构，使用 Next.js、TypeScript 和 Ant Design 开发前端界面，实现用户登录、中医药知识资源管理、知识库管理、数据导入及智能问答等功能。后端采用 Python 和 FastAPI 构建 RESTful API 服务，使用 Pydantic 进行数据校验，通过 SQLAlchemy 连接 PostgreSQL，实现用户信息、知识资源、知识库及相关业务数据的管理，并结合 Redis 实现缓存功能。 / 在知识管理方面，系统使用 Python 对导入的 PDF、Word、TXT、CSV 等格式的数据进行解析和清洗，并通过 BGE-M3 模型完成文本向量化处理，将向量数据存储于 Milvus 向量数据库中。同时，利用 PostgreSQL 存储结构化知识及知识图谱中的实体和关系，为后续检索提供数据支持。 / 在智能问答方面，系统采用检索增强生成（RAG）技术，结合规则分析与动态策略路由，根据用户问题选择合适的检索策略。通过 BGE-M3 实现稠密向量与稀疏向量双路检索，利用 RRF 算法融合检索结果，并采用 BGE-Reranker-v2-m3 模型进行重排序。在此基础上，结合知识图谱检索与证据充分性判断，将检索得到的相关知识作为上下文，调用兼容 OpenAI 接口的大语言模型生成回答，并通过流式响应返回前端，同时展示相关知识来源，提升问答结果的可追溯性。 / 最后，系统采用 Docker Compose 对前端、后端、关系型数据库、缓存及向量检索相关服务进行容器化部署，形成集知识资源管理、知识检索和智能问答于一体的中医药知识服务系统。
